# 库存健康度 Demo 策划方案

版本：v1.0
日期：2026-05-14

## Summary

做一个本地部署的前后端分离 demo，用于给老板演示“上传 ERP Excel 后，快速判断库存健不健康”。

核心流程：

1. React 前端上传 Excel。
2. FastAPI 后端解析符合 PRD 的库存明细 sheet。
3. 后端按 PRD 核心算法计算 4 个指标。
4. SQLite 保存分析任务与计算结果。
5. 前端展示 L1 概览，并支持 4 个指标分别下钻查看 L2 详情。

不做登录、免费次数、支付、导出报告、正式权限控制。

## Key Changes

- 前端：React 单页 demo，包含上传页、分析中状态、L1 概览页、4 个 L2 下钻页。
- 后端：FastAPI 提供上传分析、任务状态、概览、详情接口。
- 存储：SQLite 保存 `job_id`、文件名、数据质量、概览结果、各指标详情结果；不保存原始 Excel 文件。
- 算法：实现 PRD 核心算法，不追求生产级完整边界，但关键结果必须可信。
- 视觉：沿用 PRD 的深色驾驶舱风格，突出一句话结论、红黄绿灯、4 个指标卡片。

## Public Interfaces

后端 API 设计：

- `POST /api/jobs`
  - 入参：Excel 文件。
  - 行为：解析 Excel，识别库存明细 sheet，启动计算，返回 `job_id`。
  - 返回：`{ "job_id": "...", "status": "completed" | "failed" }`

- `GET /api/jobs/{job_id}`
  - 返回任务状态、文件名、数据范围、数据质量、错误信息。

- `GET /api/jobs/{job_id}/overview`
  - 返回 L1 概览：整体健康度、一句话结论、行动建议、4 个指标卡片。

- `GET /api/jobs/{job_id}/details/{indicator_id}`
  - `indicator_id` 支持：`total_value`、`stagnant_ratio`、`balance`、`anomalies`。
  - 返回对应 L2 图表数据、TOP 列表或异常明细。

## Implementation Plan

- Excel 解析：
  - 优先使用样表中符合契约的库存进出库明细 sheet。
  - 支持字段别名映射：物料编码、物料名称、物料规格、交易日期、交易类型、数量、金额。
  - 交易类型标准化为“入库 / 出库”。
  - 日期支持常见 Excel 日期格式。

- 数据校验：
  - 必须字段缺失时返回明确错误。
  - 数据周期少于 30 天、物料数不足、金额异常时返回失败状态。
  - 无效行可跳过并计入数据质量统计。

- 指标计算：
  - 库存总资金：入库金额减出库金额，生成月度趋势和红黄绿灯。
  - 呆滞物料占比：默认 180 天无出库，输出占比、金额、TOP 10。
  - 出入库平衡度：最近 6 个月入库/出库比，输出判断和月度对比。
  - 异常物料：检测单价突变、采购量突变、长期不出库、采购频率异常。

- 前端展示：
  - 上传成功后进入报告页。
  - L1 第一屏包含一句话结论、4 个指标卡片、数据范围、数据质量。
  - 点击卡片进入对应 L2，下钻页支持返回概览。
  - 图表可用 ECharts 或 Recharts，表格用于 TOP/异常列表。

## Test Plan

- 用现有 `机械装备企业ERP报表_4亿产值.xlsx` 上传，能生成完整概览和 4 个下钻。
- 上传缺少“交易类型”的 Excel，返回清晰错误。
- 数据周期不足 30 天时，返回“数据周期不足”。
- 人工构造健康数据，4 个指标应接近全绿。
- 人工构造严重不健康数据，4 个指标应接近全红。
- 刷新页面后，通过 `job_id` 仍能重新读取 SQLite 中的结果。

## Assumptions

- Demo 先本地部署运行，后续自行拆分部署前后端到服务器。
- 原始 Excel 上传后只用于当次解析，不落盘保存。
- SQLite 用于 demo 任务和结果持久化，不作为正式生产数据库承诺。
- 商业功能全部不做，包括登录、免费次数、支付和权限。
