# 库存健康度 · 数据契约

> **V2工厂标准工位5-①** | 版本: v1.0
> **用途**: 定义输入Excel的字段映射、数据类型、校验规则。程序员按此契约对接任意ERP导出。

---

## 1. 必须字段定义（缺一不可）

| 序号 | 字段名 | 中文变体（至少支持3种） | 数据类型 | 长度 | 可空 | 校验规则 |
|:----:|:-------|:----------------------|:---------|:----:|:----:|:---------|
| 1 | material_code | 物料编码, 物料代码, 物料编号, MaterialCode | string | 1-50 | NOT NULL | /^[A-Za-z0-9_\-]+$/ |
| 2 | material_name | 物料名称, 物料名, 品名, MaterialName, material_desc | string | 1-200 | NOT NULL | 非空 |
| 3 | material_spec | 物料规格, 规格, 型号, 规格型号, Spec | string | 0-500 | NOT NULL | 允许空字符串，但字段必须存在 |
| 4 | trans_date | 交易日期, 日期, 业务日期, 出入库日期, Date | date | YYYY-MM-DD | NOT NULL | 格式: `YYYY-MM-DD` 或 `YYYY/MM/DD` 或 `YYYYMMDD` |
| 5 | trans_type | 交易类型, 出入库类型, 类型, 收发标志, Type | string | 1-10 | NOT NULL | 值域: {入库, 出库} 或 {IN, OUT} 或 {1, -1} 或 {收, 发} |
| 6 | quantity | 数量, 出入库数量, 收发数量, Qty, 件数 | number(decimal) | 10,2 | NOT NULL | >= 0 |
| 7 | amount | 金额, 金额（元）, 单价金额, 出入库金额, Amt | number(decimal) | 16,2 | NOT NULL | >= 0。若源数据只有单价×数量，程序自动计算 |

## 2. 推荐字段定义（有则更强，无则弱化部分维度）

| 序号 | 字段名 | 中文变体 | 数据类型 | 可空 | 影响 |
|:----:|:-------|:---------|:---------|:----:|:-----|
| 8 | material_category | 物料类别, 物料分类, 品类, Category | string | NULLABLE | 无此字段则移除品类维度，不影响4个核心指标 |
| 9 | dept_name | 出入库部门, 部门, 仓库, Dept | string | NULLABLE | 无此字段则移除部门维度 |
| 10 | operator | 经办人, 制单人, 操作员, Operator | string | NULLABLE | 无此字段则移除人员维度 |
| 11 | supplier | 供应商名称, 供应商, 供货单位, Supplier | string | NULLABLE | 仅入库有值，出库一般为空。不影响核心指标 |

## 3. 字段自动识别规则

### 3.1 列名匹配（模糊匹配）

```
输入: 用户上传Excel，表头可能是任意中文名称
输出: 映射到标准字段名

匹配策略:
  1. 精确匹配       → "物料编码" → material_code
  2. 关键词包含匹配  → "物料*编码"、"物料*代码" → material_code
  3. 英文匹配       → "MaterialCode" → material_code
  4. 无匹配         → 标记为"未识别字段"，跳过不处理

匹配优先级: 精确 > 关键词 > 英文
```

### 3.2 交易类型标准化

```
输入: 交易类型列，各ERP格式不同
规则:
  "入库" / "IN" / "1" / "收" / "采购入库" / "生产入库" / "外协入库" → "入库"
  "出库" / "OUT" / "-1" / "发" / "销售出库" / "生产领料" / "委外出库" → "出库"
  其他值 → 标记为"无法识别"，该行跳过并记入异常行日志
```

### 3.3 日期格式识别

```
支持的格式（按优先级尝试）:
  1. YYYY-MM-DD      → 2025-01-15
  2. YYYY/MM/DD      → 2025/01/15
  3. YYYYMMDD        → 20250115
  4. DD/MM/YYYY      → 15/01/2025
  5. DD-MM-YYYY      → 15-01-2025
  6. Excel序列号     → 45658 (Excel内部日期数值)

解析失败 → 该行跳过并记入异常行日志
```

## 4. 数据质量检查

| 检查项 | 规则 | 失败处理 |
|:-------|:-----|:---------|
| 列数量检查 | 必须字段列≥7 | ❌ 不满足 → 退出分析，"数据格式不符合标准" |
| 空值检查 | 必须字段的空值行比例 < 10% | ❌ 超比例 → 退出分析，"数据质量过低" |
| 交易类型检查 | 入库+出库行数占比 > 80% | ❌ 不满足 → 退出分析，"交易类型不完整" |
| 日期范围检查 | 数据覆盖至少30天 | ❌ 不满足 → 退出分析，"数据周期不足" |
| 物料唯一性检查 | 至少5种不同物料 | ❌ 不满足 → 退出分析，"物料数量不足以分析" |
| 金额检查 | 总金额 > 0 | ❌ 不满足 → 退出分析，"金额数据异常" |

## 5. 数据契约示例（代码级别）

```python
# Python 数据模型示例
from pydantic import BaseModel, Field
from datetime import date
from enum import Enum
from typing import Optional

class TransType(str, Enum):
    IN = "入库"
    OUT = "出库"

class MaterialTransaction(BaseModel):
    material_code: str = Field(..., max_length=50, pattern=r'^[A-Za-z0-9_\-]+$')
    material_name: str = Field(..., max_length=200)
    material_spec: str = Field(..., max_length=500)
    trans_date: date
    trans_type: TransType
    quantity: float = Field(..., ge=0)
    amount: float = Field(..., ge=0)
    material_category: Optional[str] = Field(None, max_length=100)
    dept_name: Optional[str] = Field(None, max_length=100)
    operator: Optional[str] = Field(None, max_length=50)
    supplier: Optional[str] = Field(None, max_length=200)
```
